The authenticated suite runs with `make test-client` against seeded Laravel/PostgreSQL. It contains seven tests: four authenticated smoke/render journeys, the state-changing N2 financial/reservation journey, the continuous P3-02 client loop, and the P3-03 queued PDF/CSV/XLSX plus guest-phone artifact journey. `make test-api-postgres` uses the isolated `inn_test` database for production-engine constraints, uniqueness, and row-lock races; `make test-documents-exports` is the focused PostgreSQL artifact gate.

P3-06A is implementation-complete and materially provider-tested, but it is not sandbox-complete against the runbook's Argentina/ARS release gate. On 2026-08-19, a Colombia/MCO test seller and buyer completed a real COP 10,000 Checkout Pro approval. A correctly signed public HTTPS delivery was accepted, the worker performed an authoritative lookup, and duplicate delivery plus three browser refreshes left exactly one payment, one paid deposit, and one folio payment line. A COP 2,000 partial refund was completed in Mercado Pago's seller UI after the provider rejected the refund API call on account policy; authoritative refund lookup then completed exactly one Inn refund and one refund folio line. Both immutable receipt PDFs downloaded through the authenticated endpoints and rendered cleanly. Provider payment `…7197` and refund `…6852` are recorded only in redacted form here; no credential, access token, signature, webhook secret, or public-link token is retained in Git.

The remaining WP-11 blockers are provider/account-country specific: the runbook requires an Argentina test seller/buyer and ARS journey; the available personal developer account is Colombia/MCO. Mercado Pago's hosted Colombia flow disabled the final action for `CONT`/`OTHE` manual test-card simulations after labeling the card source `UNDEFINED SOURCE`, direct payment/refund API calls returned the provider policy denial, and no provider-originated webhook delivery was observed. The PR must therefore remain draft and described as deterministic implementation plus MCO provider evidence. Do not start [P3-06B](p3-06b-front-desk-tenders-implementation-plan.md) until the Argentina WP-11 gate is completed or the release owner explicitly changes the country/currency acceptance criterion.
